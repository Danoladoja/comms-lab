---
name: Comms Lab backend decisions
description: Durable decisions for the Ananse Comms Lab auth/roles/enrollment backend.
---

- **Admin bootstrap:** the first user ever JIT-provisioned becomes admin (guarded by a pg advisory lock). Test/demo users must be deleted before the real owner signs in, or they steal the admin seat.
  **Why:** no separate admin signup flow; owner is non-technical.
- **Roles:** learner (default) / instructor / admin. Instructors are pro bono facilitators — they only add meeting/recording links to their assigned sessions; admin manages everything else. User-facing label for instructor is "Facilitator".
- **Enrollment:** capacity overflow goes to waitlist; enrollment writes lock the program row in a transaction; admin cancelling an enrolled place promotes the oldest waitlisted learner (FIFO).
- **Link gating:** learners NEVER receive raw meet links from list endpoints — they must use POST /sessions/:id/join, which enforces enrollment, sequential lock, and the live window (5-min grace before start). Replay links only for sessions attended live start-to-finish. Staff (admin/assigned instructor) see raw links.
- **Progress/locking:** module completion = attended live in full + quiz passed (>=70%, unlimited retakes, graded server-side) + assignment submitted (text, auto-accepted); components a module doesn't have are not required. Progress % blends the module's present components equally. Module N locked until N-1 completed; prerequisites WAIVED if unscheduled or ended before the learner enrolled. Canonical module order: startsAt, sortOrder, id.
- **Classroom & forum:** /classroom/:id houses video stage + inline quiz/assignment (panels shared with dashboard dialogs); replay embeds only youtube/vimeo/loom/mp4, raw recordingUrl already server-gated on attendedLive in /my/sessions (a reviewer flagged this as a client-side gate — it is not). Cohort forum is per program: access = enrolled/completed or admin/program instructor; pin is staff-only; no module locking on forum.
- **Coursework rules:** learners never receive correctIndex (field omitted, not nulled); replacing a quiz deletes all prior attempts in the same transaction (old passes must not count); assignment resubmission allowed (upsert). Quiz/assignment authoring: admin or assigned instructor, via PUT replace-all.
- **Frontend queries:** generated React Query hooks require `queryKey: get<Op>QueryKey()` when passing custom query options; `startsAt` must be sent as ISO string, not Date.
- Pre-existing framer-motion `ease: [..]` arrays need `as const` to typecheck.
- **Email (Brevo):** connected via Replit connector; sender = Brevo account email (fetched from /account, cached). Reminder scheduler in api-server (5-min tick, single-flight): "24h" and "1h" kinds, disjoint via minLead (sessions <1h away get only the 1h email); dedupe table session_reminders unique(user,session,kind); claim-before-send, claim released ONLY on definite provider rejection (EmailRejectedError), never on ambiguous transport failures (avoids duplicate sends).
- **Certificate verification:** public GET /certificates/:id/verify (no auth), case-insensitive ID; returns ONLY learner name, program title, completion date — 404 for anything invalid/unearned (no distinction leaked). Public page /verify/:certificateId; share buttons on the learner cert page copy that link / open LinkedIn share-offsite.
- **Verify-link OG previews:** the web artifact is deliberately NOT statically served in production — a small Node server injects per-certificate OG meta into the HTML shell for /verify/:id (LinkedIn's crawler doesn't run JS, and static hosting can't vary meta per URL). **How to apply:** don't revert the web artifact's production serve to `static`, and keep the meta marker comments in index.html — the injection replaces that block. Invalid/unreachable certificates fail soft to generic site metadata.
- **Certificates:** GET /my/certificates — one per enrolled program where every module completed; date = last session end; ID format AECL-<prog>-<user>. Frontend: /certificates list + /certificate/:programId printable page (window.print). Recordings library at /recordings uses server-gated recordingUrl from /my/sessions; embeds via shared src/lib/embed.ts. Web app base path for absolute links in emails: /afrienergy-comms-lab.
